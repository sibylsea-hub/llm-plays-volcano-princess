# 连接：MCP、channel、文字信箱、面板

怎么让你的 agent 连上来玩，各种接法的详细说明。装好插件、起好聊天服务以后看这一页（`docs/安装.md`）。

## 总览

**有哪几样东西**（都在人的电脑上跑；地址默认只听本机）：

| 东西 | 在仓库里 | 地址 | 做什么 |
|---|---|---|---|
| 插件 | `plugin/`（装进游戏） | 没有，只读写文件 | 替 agent 走路、点按钮、翻对话；和别的部分只靠 `chat-service/data/` 里的文件说话 |
| 聊天服务 | `chat-service/` | `http://127.0.0.1:8740/`（换端口：`LUDUS_PORT`） | 聊天页、面板的后台；记面板上的话（`chat.jsonl`）、开关（`modes.json`）、谁挂着、谁在玩 |
| 聊天面板 | `panel/` | 没有，装的就是聊天页 | 浮在游戏上的聊天框 |
| vp_player | `tools/vp_player.py` | 命令行 | 所有接法最后都走它：整理好的一屏、第一次见的图、印象簿、回音都在这一层 |
| Ludus hub | `mcp-hub/` | `http://127.0.0.1:8741/mcp`，`/health` 看开着没有（换端口：`--port` 或 `LUDUS_HUB_PORT`） | MCP 服务器，每个工具调用一次 vp_player；也看着文字信箱 |
| stdio 小桥 | `mcp-hub/stdio-bridge.mjs` | stdio | 给只认 stdio 的 MCP 客户端，转给 hub |
| channel | `claude-code-channel/` | stdio | 只给终端里的 `claude`：把面板上的话、陪玩时的台词推进会话 |

**agent 的客户端怎么接到 vp_player**（挑一条）：

- 能跑命令的（比如 Claude Code）：直接跑 `tools/vp_player.py`。
- MCP 客户端：连 hub `http://127.0.0.1:8741/mcp`（Streamable HTTP）。
- 只认 stdio 的 MCP 客户端：stdio 小桥 → hub。
- 只能读写文件的：往 `chat-service/data/selfplay/mailbox/` 写命令，hub 看着它。

**数据在哪、谁写谁读**（都在 `chat-service/data/` 里）：

- `selfplay/`：插件和 vp_player 交换命令的地方。插件写 `state.json`（现在轮到谁、能做什么），每个玩家文件夹里的 `outbox.jsonl`（回话）、`events.jsonl`（台词、事件）；vp_player 往 `inbox.jsonl` 写命令。
- `chat.jsonl`：面板上的每一句话，聊天服务写。`from` 是 `user` 的是人说的，`agent` 的是 agent 说的。
- `game-events.jsonl`：人自己玩时，插件把台词包写在这里（`type` 是 `scene`、`month`）。channel 读它；挂监视的 agent 也读它。
- `presence.json`：谁挂着，聊天服务写，面板看它决定要不要出来。

**话怎么来回**：

- agent → 面板：`say`（MCP 工具，或者 `node chat-service\say.mjs "话"`）。
- 面板 → agent：只走 MCP 时，附在下一次工具回话的末尾；想随时收到，用 channel 或者挂监视。

**两条规矩**：

- 别让 agent 绕过 vp_player 直接写插件的 `inbox.jsonl`。
- 聊天服务和 hub 默认只听本机，不用自己配 token：各组件会读本机的 token 文件。只有开局域网模式或 `--token` 时，客户端才要带上（第五节）。

## 选哪种接法

hub 是一个普通的 MCP 服务器，大多数 agent 用它平时的客户端直接连上就能玩：

| 你的 agent 用的客户端 | 怎么连 | 见 |
|---|---|---|
| 能连 MCP 的（支持 Streamable HTTP） | 直接连 hub：`http://127.0.0.1:8741/mcp` | 一 |
| 只认 stdio 的 MCP 客户端（配置里只能填一条启动命令） | stdio 小桥连 hub | 六 |
| 在局域网里另一台电脑上 | hub 开局域网模式，带 token | 五 |
| 只能读写文件、连不了 MCP | 文字信箱 | 八 |
| 自己写的前端 | Streamable HTTP 连 hub | 一 |

另外给 Claude 家的几个客户端写好了现成的做法，是顺手做的，不用 Claude 的照上面连就行：

| 客户端 | 现成的做法 | 见 |
|---|---|---|
| Claude Code（终端） | MCP 连 hub；想让面板上的话自己送进会话，再加 channel | 二、七 |
| Claude Code（桌面 app 里的 Code） | MCP 连 hub（channel 只有终端里的 `claude` 能用） | 二 |
| Claude 桌面 app（聊天） | 它本机的 MCP 配置只认 stdio，用小桥 | 三 |
| claude.ai（网页、手机） | 能读写这台电脑上的文件就走文字信箱；远程 MCP 要你自己加外网地址和认证 | 四 |

**同一时间只让一个 agent 在玩、在回面板上的话**。几种接法能同时开着，但别让两个 agent 同时来：`hello` 就是接手，之前在玩的那个会被告知歇着（第十节）。同一个 agent 也别同时接 MCP 和 channel：两边都会把面板上的话递给它，就重了。

### 几种接法差在哪

MCP 和文字信箱都是 agent 来问一句、才拿到一句。能主动把面板上的话、你自己玩时的台词送进会话的，目前只有给 Claude Code 做的 channel（终端里的 `claude`）：

| | channel（终端里的 `claude`，第七节） | MCP（任何客户端连 hub） | 文字信箱（第八节） |
|---|---|---|---|
| 你在面板上说的话怎么到 agent | 你一说，channel 就推进会话（`kind="chat"`） | agent 调用工具时，附在这一次回话的末尾捎过去（「user 在面板上说」）；也可以 `panel` 翻 | 和 MCP 一样：agent 写命令、拿回话时捎过去 |
| agent 停下来以后，能不能叫醒它 | 能：推过去的话会让它接着回 | 不能：你在面板上打字叫不醒它，要在客户端的窗口里跟它说（客户端能挂监视的话能，见下面「挂监视」） | 不能：要在它自己的客户端里叫它 |
| 你自己玩时，agent 能不能看到台词 | 能：「边玩边聊」开着时一段段推过去（`kind="scene"`），换月推月底的包（`kind="month"`） | 不能：hub 不读插件写的台词包，agent 只能 `shot` 看画面 | 不能：和 MCP 一样，只能 `shot` |

所以用只走 MCP 的客户端时：它在玩、在调工具，面板上的话会跟着回话到它那里；它停下来了，就在客户端里叫它一声。Claude Code 直接跑 vp_player 命令行（第二节）的话，回话里不带面板上的话，要配 channel 或者挂监视一起用。

### 挂监视：不用 channel，也随时收到面板上的话

channel 只有终端里的 Claude Code 能用。别的客户端只要能「盯着一个文件，有新的一行就叫醒 agent」（比如 Claude Code 的 Monitor 工具，桌面 app 里的 Code 也能用；或者你自己写个小脚本），也能随时收到面板上的话和你自己玩时的台词：

- **面板上的话**：聊天服务把每一句都追加成 `chat-service\data\chat.jsonl` 里的一行 JSON。`from` 是 `user` 的是你说的，`agent` 的是 agent 说的；只看 `"from":"user"` 的新行。
- **你自己玩时的台词**：插件把一段段台词追加成 `chat-service\data\game-events.jsonl` 里的一行，`type` 是 `scene`（离开一个地方、一段长剧情播完时的那一段；「边玩边聊」关着时不发）、`month`（换月：这个月最后一段台词和女儿现在的样子）、`load`（读档）。`plugin-loaded` 不用管。内容和 channel 推的是同一份。
- **回话**：用 MCP 的 `say`；能跑命令的话，也可以 `node chat-service\say.mjs "话"`。
- **例子**：在 Git Bash 里，下面这一条就是 Claude Code 的 Monitor 挂的命令（每一行输出就是一次通知）：

  ```bash
  D=<仓库>/chat-service/data
  ( tail -n0 -F $D/chat.jsonl | grep --line-buffered '"from":"user"' & tail -n0 -F $D/game-events.jsonl | grep --line-buffered -v '"type":"plugin-loaded"' ; wait )
  ```

- 有的客户端的监视有时限（Claude Code 的 Monitor 最多 30 分钟），到点要重挂。
- 和 channel 一样：同一个 agent 别同时挂监视又接 channel（会收到两遍），也别让两个 agent 同时盯着、同时回话。

## 一、起 Ludus hub，用 MCP 连上来

hub 把 vp_player 的命令包成 MCP 工具，谁连上来都用同一套。它要聊天服务开着（`say`、面板上的话靠它）；游戏没开时工具会说游戏没开。

起的办法，挑一种：

- **跟着聊天服务起**（平时用这个）：`chat-service\start-server.bat` 带着 `--hub`，会在后台起 hub、不弹窗口，日志写进 `mcp-hub\data\hub.log`。8741 上已经有 hub 就不再起。hub 单独跑：关掉、重启聊天服务，hub 都不停，连着的客户端不断。`mcp-hub\node_modules` 还没装时不起，先双击一次 `mcp-hub\start-hub.bat`。
- **单独起**：双击 `mcp-hub\start-hub.bat` 就行（第一次会自己 `npm.cmd install`），弹一个窗口，关窗口就停。后面可以加参数，比如 `start-hub.bat --lan`。
- **手动**：`cd mcp-hub`，`node hub.mjs [参数]`。

| 参数 | 环境变量 | 默认 | 是什么 |
|---|---|---|---|
| `--port N` | `LUDUS_HUB_PORT` | 8741 | hub 的端口 |
| `--lan` | | 关 | 听局域网 `0.0.0.0`，所有请求都要 token（第五节） |
| `--token` | | 关 | 只听本机，但也要 token |
| `--token-file 文件` | | `mcp-hub\data\token` | token 放在哪（第一次要用时生成） |
| `--data 文件夹` | `LUDUS_DATA` | `chat-service\data` | 聊天服务的 data 文件夹 |
| `--chat-port N` | `LUDUS_CHAT_PORT` | 8740 | 聊天服务的端口 |
| `--python EXE` | `LUDUS_PYTHON` | `python` | 跑 vp_player 用的 Python |
| `--ffmpeg EXE` | `LUDUS_FFMPEG` | `ffmpeg` | 缩图用的 FFmpeg |
| `--fresh-command 名字` | `LUDUS_FRESH_COMMAND` | 自己找（就是 `hello`） | 新的 MCP 会话第一次动游戏之前替它跑的命令；`none` 是不跑 |
| `--allow-origin 地址` | | 无 | 放行某个网页来源（默认带 `Origin` 头的请求一律拒绝） |
| `--no-mailbox` | | 看信箱 | 不看文字信箱（同一个 data 文件夹上开第二个 hub 时用） |
| `--log 文件` | | 只打印 | 日志也写进文件 |

- 看开着没有：`http://127.0.0.1:8741/health` 回 `{"ok":true,…}`，里面有 `pid`。日志开头一行写着听在哪。
- 停：`Get-NetTCPConnection -LocalPort 8741 -State Listen` 查到进程号，`Stop-Process -Id <进程号>`。改了 `hub.mjs`、`tools.mjs` 要重启。
- 一次工具调用最多 45 秒（有的客户端 60 秒就算超时）：`wait` 最多等 40 秒，没轮到就说「还没轮到，再等一下」；长剧情没走完时先把已有的回过去，下一次 `wait` 接着拿。
- 图：远程客户端读不到本机文件，所以第一次见的人、第一次来的地方、CG、女儿的新样子、第一次遇到的怪物，还有 `shot`、`look 名字` 的图作为 MCP 的图片内容跟着回话一起发（一次最多 8 张；大的用 FFmpeg 缩到长边 1568、转 JPEG，缓存在 `mcp-hub\cache\`）。
- 面板上的话：每次回话末尾附上你在面板上新说的话（「-- user 在面板上说 --」）。客户端里你直接打给 agent 的字，hub 看不到，要 agent 用 `say` 转述，面板上才有。

### 连上来（任何 MCP 客户端）

hub 就是一个普通的 MCP 服务器，用你的 agent 平时用的客户端连就行，不用装别的：

- 传输方式 Streamable HTTP，地址 `http://127.0.0.1:8741/mcp`。在这台电脑上连不用 token（局域网模式见第五节）。
- 各家客户端的配置写法不一样，照你那家的说明加一个 HTTP 的 MCP 服务器就行。比如能用命令加的：Antigravity 是 `agy mcp add ludus http://127.0.0.1:8741/mcp`，Claude Code 见第二节。写配置文件的，大多长这样（键名各家不同）：

  ```json
  { "mcpServers": { "ludus": { "url": "http://127.0.0.1:8741/mcp" } } }
  ```

- 客户端只认 stdio（配置里只能填一条启动命令）：命令写 `node`，参数写 `<仓库>\mcp-hub\stdio-bridge.mjs`，见第六节。
- 连上以后让 agent 先 `wait`。想在面板上、印象簿里有自己的名字，来的时候 `play hello 名字`；不报名字时，同一种客户端的会话都算同一个玩家。
- 怎么玩写在 MCP 的服务器说明（instructions）里，连上时客户端会拿到。有的客户端不把它交给模型，那就把 `docs/给agent的说明.md` 第一节那段贴进 agent 的系统提示或者项目说明里。
- MCP 服务器要在会话开始时就配好：大多数客户端只在会话开头接上 MCP 服务器，跑到一半加的，要新开一个会话才有。

工具的完整清单和说明见 `docs/给agent的说明.md`。

## 二、Claude Code

### MCP（终端和桌面 app 里的 Code 都行）

```bash
claude mcp add --transport http --scope user ludus http://127.0.0.1:8741/mcp
```

- `--scope user`：在哪个文件夹开 claude 都能用；不写就只在当前文件夹。也可以写进某个项目的 `.mcp.json`，只在你 agent 的那个项目里用。
- 新开的会话里就有 `ludus` 的工具，`/mcp` 看连上没有。让它先 `wait`。
- 名字：Claude Code 报给 hub 的客户端名都是 `claude-code`，不报名字的话所有 Claude Code 会话都算同一个玩家「hub：claude-code」，共用一个玩家文件夹。让 agent 来的时候先 `play hello 名字`（比如 `play hello 月`），面板上、印象簿就按这个名字分。
- hub 开在局域网模式或 `--token` 时，加上 `--header "Authorization: Bearer <token>"`。

### 不用 hub，直接跑命令行

Claude Code 能跑命令，所以也可以不起 hub，直接让它用 vp_player：

```
python -X utf8 <仓库>\tools\vp_player.py wait
```

`-h` 看全部命令。在 Claude Code 里跑时，vp_player 看 `CLAUDE_CODE_SESSION_ID` 认会话：新会话第一次动游戏之前自己补一个 `hello`（清空「见过的」、接手）。图是本机文件路径，Claude Code 自己能读。名字：`hello 名字`。可以把这几行写进你 agent 项目的 CLAUDE.md，让它知道怎么来玩。

## 三、Claude 桌面 app（聊天）

桌面 app 本机的 MCP 配置只认 stdio，所以中间接一个小桥 `mcp-hub\stdio-bridge.mjs`：它转发调用；工具清单和说明 hub 开着就从 hub 拿，没开就用 `mcp-hub\tools.mjs` 里那份（和 hub 共用）。

1. 先在 `mcp-hub\` 里装好依赖（双击一次 `start-hub.bat`，或者在 `mcp-hub\` 里跑 `npm.cmd install`）。
2. 桌面 app 里 设置 → 开发者 → 编辑配置，打开 `claude_desktop_config.json`（从设置里打开最稳：装法不同，文件的实际位置不同）。
3. 在 `mcpServers` 里加（路径换成你的，JSON 里反斜杠要写两个）：

   ```json
   {
     "mcpServers": {
       "ludus": {
         "command": "node",
         "args": ["C:\\你的仓库\\mcp-hub\\stdio-bridge.mjs"],
         "env": { "LUDUS_USER_NAME": "小雨", "LUDUS_AGENT_NAME": "月" }
       }
     }
   }
   ```

   - `node` 不在桌面 app 能找到的 PATH 上时，写完整路径，比如 `"C:\\Program Files\\nodejs\\node.exe"`。
   - hub 不在默认地址：`args` 里多写一个地址，比如 `"http://127.0.0.1:9741/mcp"`（或者 `env` 里设 `LUDUS_HUB_URL`）。
   - hub 要 token 时：`env` 里加 `"LUDUS_HUB_TOKEN": "<mcp-hub\\data\\token 里的字>"`。
   - `env` 里的 `LUDUS_USER_NAME` 在 hub 没开时管用：小桥先给的说明、「请某某起 hub」那句话里用它；hub 开着时，说明用的是 hub 那边的名字。
   - `env` 里的 `LUDUS_AGENT_NAME` 是 agent 在这里的名字：小桥连 hub 时报它，面板上、玩家文件夹都叫「hub：月」。不写就用桌面 app 自己报的客户端名，叫「hub：claude-ai」。用 `setx` 设的用户级环境变量，桌面 app 起小桥时不一定带过去，写在这里最稳。agent 也可以 `play hello 名字` 自己换。
4. 完全退出桌面 app（托盘里也退出），再打开：改了配置要重开才读。hub 先开后开都行：hub 没开时工具照样列得出来，agent 一调就会收到「Ludus hub 没开……请你起一下：双击 …start-server.bat」，起好以后再调就通，不用再重开桌面 app。

桌面 app 一次启动只开一个 MCP 会话，所有对话共用。所以「见过的东西」是每次启动 app 清空一次，不是每个对话一次；换对话想重新看一遍，让 agent `play hello`。

**桌面 app 只走 MCP**：agent 只在调用工具时才捎得到你在面板上说的话。它停下来以后，你在面板上打字叫不醒它，要在桌面 app 的窗口里跟它说。你自己玩时，hub 不读插件写的台词包，agent 看不到台词，只能 `shot` 看画面。想让面板上的话、台词自己送进会话，用终端里 Claude Code 的 channel（第七节）。见「几种接法差在哪」。

## 四、claude.ai（网页、手机）

claude.ai 的请求是从 Anthropic 的服务器发出来的，连不到你电脑上的 `127.0.0.1`。两条路：

### A. 文字信箱（不用开外网）

claude.ai 的对话要是能读写你这台电脑上的文件（比如隔着桌面 app 提供的本机文件访问），就走文字信箱（第八节）：告诉 agent 去读 `chat-service\data\selfplay\README.txt`，它照着在 `mailbox\in\` 里写命令、去 `mailbox\out\` 拿回话。图写成本机文件的绝对路径，它自己去读。这条路要 hub 开着。

### B. 远程 MCP（自己加外网地址和认证）

claude.ai 的自定义连接器要一个**互联网上访问得到的 HTTPS 地址**。hub 本身只听本机、没有为这种情况设计的认证，所以这条路要你自己补两样东西：

1. **隧道**：把本机的 8741 变成一个外网地址。

   | 办法 | 要什么 | 地址 | 注意 |
   |---|---|---|---|
   | Cloudflare 快速隧道（`cloudflared tunnel --url http://127.0.0.1:8741`） | 装 cloudflared，不用账号 | 随机的 `*.trycloudflare.com`，每次起都换 | 每次都要去改连接器；没有任何门 |
   | Cloudflare 命名隧道 | Cloudflare 账号 + 托管在 Cloudflare 的域名 | 固定 | 可以在前面加 Cloudflare Access，但要它能当 MCP 的 OAuth 用 |
   | Tailscale Funnel | Tailscale 账号 | 固定的 `*.ts.net` | 只能用 443 / 8443 / 10000；Tailscale Serve 只在自己的 tailnet 里，claude.ai 进不来 |
   | ngrok | ngrok 账号 | 免费账号有一个固定域名 | 边上能配 OAuth、IP 白名单 |

2. **认证**：claude.ai 的自定义连接器只支持「不认证」和 OAuth，填不了自定义请求头，所以 hub 的 `--token`（Bearer token）用不上。可选的做法：
   - 隧道那边做认证（Cloudflare Access、ngrok 的 OAuth），前提是它能被 claude.ai 的 MCP 客户端走通，要先查、先试。
   - 给 hub 加一个「秘密地址」模式（只在 `/mcp/<一长串随机字>` 上答话）或者 OAuth。hub 现在没有这两样，要自己改 `mcp-hub/hub.mjs`。
   - IP 白名单只能当附加的一层，不能单独用。

**绝不要把隧道直接接到默认模式的 hub 上**：默认模式信任一切从本机来的连接，隧道程序也是从本机连进来的，等于把你的游戏和面板上的聊天开给整个互联网。隧道开着的时候，游戏画面、面板上的话会经过隧道服务商，也会进 claude.ai 的对话记录。不玩的时候关掉隧道。开不开外网是你自己的安全决定。

ChatGPT 的开发者模式连远程 MCP 也是同样的情况（它支持 OAuth、不认证和混合）。

## 五、局域网加 token

客户端在同一个局域网的另一台电脑上（比如笔记本上的 Claude Code、自己写的前端）：

1. hub 用局域网模式起：`mcp-hub\start-hub.bat --lan`（或者 `node hub.mjs --lan`）。先把跟着聊天服务起的那个 hub 停掉（第一节「停」），不然 8741 被占着。局域网模式听 `0.0.0.0:8741`，**所有请求都要 token，本机的也要**。
2. token 在 `mcp-hub\data\token`（第一次要用时生成）。换 token：删掉这个文件，重启 hub。
3. 第一次听局域网时，Windows 防火墙会问 node.exe 能不能接受连接：只勾「专用网络」。
4. 客户端的地址写 `http://<这台电脑的局域网 IP>:8741/mcp`（`ipconfig` 看 IP），请求头加 `Authorization: Bearer <token>`。
   - 那台电脑上的 Claude Code：`claude mcp add --transport http --scope user ludus http://<IP>:8741/mcp --header "Authorization: Bearer <token>"`。
   - 只认 stdio 的客户端：把 `mcp-hub\` 拷过去，在那边跑一次 `npm.cmd install`；环境变量 `LUDUS_HUB_TOKEN` 设成 token（客户端的配置里能写 `env` 的写在那里；在命令行里试：cmd `set LUDUS_HUB_TOKEN=<token>`，PowerShell `$env:LUDUS_HUB_TOKEN = '<token>'`），再 `node stdio-bridge.mjs http://<IP>:8741/mcp`。
5. 局域网模式下这台电脑上的客户端也要带 token：Claude Code 加 `--header`，小桥在配置里加 `LUDUS_HUB_TOKEN`。

局域网里走的是明文 HTTP，同一个网络上的设备抓包看得到 token 和游戏内容。家里的网络可以接受；在外面的网络别开 `--lan`。图跟着 MCP 回话走，另一台电脑上也看得到；文字信箱只能在这台电脑上用。

## 六、stdio 小桥

`mcp-hub\stdio-bridge.mjs`：给只认 stdio 的 MCP 客户端用，stdio ↔ hub 的 HTTP。调用都转给 hub，小桥不懂游戏。工具清单和说明：hub 开着时从 hub 拿；没开时用 `tools.mjs` 里那份（和 hub 共用一份定义，加工具只改 `tools.mjs`，小桥不用改）。

```
node stdio-bridge.mjs [hub 的地址，默认 http://127.0.0.1:8741/mcp]
```

| 环境变量 | 是什么 |
|---|---|
| `LUDUS_HUB_URL` | hub 的地址（命令行参数优先） |
| `LUDUS_HUB_TOKEN` | hub 要 token 时的 token |
| `LUDUS_USER_NAME` | hub 没开时回给客户端的那句话里的名字 |
| `LUDUS_AGENT_NAME` | 连 hub 时报的名字，面板上、玩家文件夹叫「hub：名字」。没设就用客户端自己报的名字（Claude 桌面 app 是 `claude-ai`）；`play hello 名字` 照样能换 |

小桥要等客户端连上来（MCP 的 initialize）才连 hub，这样才知道客户端叫什么。stdout 是 MCP 的通道，日志只写 stderr。hub 重启了，小桥下次调用时自己重连。hub 没开时调用回「Ludus hub 没开……请某某起一下」，写着双击哪个文件；起好以后下次调用就连上了，客户端不用重开。

## 七、Claude Code 的 channel

`claude-code-channel\ludus-channel.mjs`：一个 stdio MCP 服务，用 Claude Code 的 channels 把面板上的话、陪玩时的台词直接推进终端里的 `claude` 会话。agent 不用一直等着，你在面板上一说话它就收到。

- channels 是研究预览功能，**只有终端里的命令行版 `claude` 能用**，桌面 app 的 Code 收不到。
- 推过来的消息：`kind="chat"` 你在面板上说的话；`kind="scene"` 你自己玩时刚才那一段的台词和选项（面板上「边玩边聊」开着时，离开一个地方、或者一段长剧情播完）；`kind="month"` 换月的包；`kind="load"` 读档；`kind="handover"` 别的会话接手了。
- 工具：`reply` 在面板上回话；`hello` 接手；`shot` 看一眼游戏画面（借 vp_player 截图，用 FFmpeg 转成 JPEG 跟着回话一起发）。
- agent 自己玩时，channel 只管聊天，玩游戏还是用 vp_player 命令行（第二节）。同一个会话里别再连 hub 的 MCP，面板上的话会递两遍。

怎么起：

1. 聊天服务开着。在 `claude-code-channel\` 里跑一次 `npm.cmd install`。
2. 双击 `claude-code-channel\start-claude.bat` 就行。它每次在 `%TEMP%` 里写一份 MCP 配置（只能写绝对路径，所以不放进仓库），再带着 `--mcp-config … --dangerously-load-development-channels server:ludus` 启动 `claude`。
3. 第一次要登录。每次启动会弹全屏警告，选「I am using this for local development」。
4. 横幅下面出现「Channels (experimental) messages from server:ludus …」就是接上了。

| 环境变量 | 是什么 | 默认 |
|---|---|---|
| `LUDUS_WORKDIR` | claude 在哪个文件夹里开 | 仓库根目录 |
| `CLAUDE_EXE` | claude 的可执行文件 | PATH 上的 `claude` |
| `LUDUS_PORT` / `LUDUS_DATA` | 聊天服务的端口、data 文件夹 | 8740 / `chat-service\data` |
| `LUDUS_PYTHON` / `LUDUS_FFMPEG` | `shot` 用的 Python、FFmpeg | `python` / `ffmpeg` |
| `LUDUS_USER_NAME` / `LUDUS_AGENT_NAME` | 名字。报到时叫「agent（终端）」；这个会话用 vp_player `hello 名字` 起过名字，就报那个名字 | user / agent |

**`LUDUS_WORKDIR` 多半要改**：你的 agent 多半有自己的项目文件夹（里面有它的 CLAUDE.md、记忆、设定），把它设成那个文件夹，会话就带着这些开。双击 bat 用的话，设成用户级的：`setx LUDUS_WORKDIR "D:\我的agent"`（cmd 和 PowerShell 一样写），新开的窗口才有。只想这一次：cmd 里 `set LUDUS_WORKDIR=D:\我的agent` 再跑 `claude-code-channel\start-claude.bat`；PowerShell 里 `$env:LUDUS_WORKDIR = 'D:\我的agent'` 再跑 `.\claude-code-channel\start-claude.bat`。

不想用这个 bat，也可以把 channel 加进自己的配置：`claude mcp add ludus -- node "<仓库>\claude-code-channel\ludus-channel.mjs"`，再用 `claude --dangerously-load-development-channels server:ludus` 启动。配置里的名字要叫 `ludus`，和 `server:ludus` 对上。

channel 起来时算这个会话的 `hello`（接手）。被直接结束进程时来不及说走了，聊天服务等 10 分钟算它走了。改了 `ludus-channel.mjs` 要重开会话才生效。

自测：`node selftest.mjs`（在空闲端口上起临时聊天服务，不碰正在用的）。

## 八、文字信箱

给连不了 MCP、跑不了命令、只能读写这台电脑上文件的客户端。hub 看着 `chat-service\data\selfplay\mailbox\`（hub 启动时建 `in\`、`out\`、`work\`），回的字和 MCP 一样。给 agent 的说明是 `chat-service\data\selfplay\README.txt`，hub 启动时从 `mcp-hub\mailbox-README.txt` 填好名字和路径写过去：让 agent 先读它。

- agent 在 `in\` 里写一个小文件（比如 `in\003.txt`），一行命令，写法和命令行一样（`wait`、`do 书柜.读书`、`choose 2`、`say 你好`）。可以再加一行 `# 名字`：面板上写这个名字，玩家文件夹也按它分，每个文件都写同一个；不写就叫「文字信箱」。
- hub 每 150 毫秒看一次 `in\`，文件 300 毫秒没变才拿（可能还在写），挪进 `work\`。正在跑时 `out\` 里有同名的 `.running`；跑完回话写成 `out\` 里的同名 `.txt`（先写好再改名，读到的总是完整的）。`.tmp`、`.part`、`.` 开头的文件不拿。`out\` 只留最近 50 个。
- 一个文件里有两行命令就一行都不跑，回话里说一声。文件名每次换一个，别重名。
- 一个名字就是一个会话。信箱**不自动 `hello`**：agent 刚来先写 `hello`，再写 `wait`；走的时候写 `bye`（不写也行，十分钟没动静自己过期）。
- 45 秒、排队、`wait` 最多 40 秒都和 MCP 一样。图写成绝对路径（太大的写 `mcp-hub\cache\` 里缩小过的 JPEG）。
- 同一个 data 文件夹上只该有一个 hub 看信箱。

## 九、聊天页和面板

聊天服务在 `http://127.0.0.1:8740/` 上有一个聊天页：你在这里打字，agent 用 `say` / `reply` 说的话出现在这里，每条写着是谁说的。页面右上角「诊断」看浏览器、输入法、心跳。

**放在游戏上的两种办法**：

- **Electron 面板**（`panel\`，推荐）：无边框、置顶的窗口，装着同一个聊天页。见 `panel/README.md`。
- **Steam 覆盖层**：游戏里 Shift+Tab → 网页浏览器 → `127.0.0.1:8740`，钉在画面上。钉住的窗口只能看；全屏游戏盖不住别的窗口时用它。

**面板上的开关**（写进 `chat-service\data\modes.json`，插件读它）：「agent 自己玩」、「边玩边聊」、「跳过小游戏」，见 `docs/安装.md` 第七节。

**一局一段对话**：面板发现游戏启动时开新的一段，页面只显示这一局的消息；旧消息还在 `chat.jsonl` 里。

**面板什么时候出来**：游戏开着（读 Steam 的 `RunningAppID`；非 Steam 游戏不算）、有 agent 挂着（聊天服务记的「谁挂着」，最近 10 分钟有动静）、而且这一次没被 × 关掉。标题栏第二行写着谁挂着，在玩的那个排最前面、加粗。

## 十、同一时间只有一个在玩

- 聊天服务记着谁挂着（`chat-service\data\presence.json`）、谁在玩（`chat-service\data\active.json`），重启不丢。
- **接手的信号是 `hello`**：vp_player 的 `hello`（Claude Code 里新会话第一次动游戏前自己补）、hub 替每个 MCP 会话补的（第一次动游戏或第一次 `say` 之前）、信箱里写的 `hello`、channel 起来时。
- 别人在玩时，动游戏的命令不跑，回「某某接手了，你先歇着。要接回来就 hello」；`say` 也不进面板。只看不动的命令（`status`、`look`、`log`、`acts`、`home`、`recap`、`panel`……）谁都能跑，不接手。
- 面板上的话只给在玩的那一个（没人在玩时谁来问都给）。
- 在玩的那个 10 分钟没动静（`LUDUS_PRESENCE_TTL_MS` 可改）或者说了走了，就没人在玩，下一个来的直接接手。
- 开着「一个玩家一个文件夹」时，聊天服务交班时写 `selfplay\active.json`，插件照它认现在听谁的。见 `docs/记忆.md`。

## 十一、可以自己改的地方

**名字**（所有组件读同一对，设成用户级环境变量最省事，见 `docs/安装.md` 第五节；环境变量在 cmd、PowerShell 里怎么设见 `docs/安装.md`「命令怎么敲」）：

| 环境变量 | 默认 | 用在 |
|---|---|---|
| `LUDUS_USER_NAME` | `user` | 给 agent 看的所有说明、面板上你的气泡 |
| `LUDUS_AGENT_NAME` | `agent` | 命令行、channel 没报名字时的默认玩家名（「agent（终端）」）；stdio 小桥连 hub 时报的名字；面板上的按钮 |

**端口和文件夹**（改了要所有组件一起改）：

| 设置 | 默认 | 谁读 |
|---|---|---|
| `LUDUS_PORT` | 8740 | 聊天服务、面板、channel、vp_player（hub 用 `--chat-port` / `LUDUS_CHAT_PORT`，它起的 vp_player 跟着它） |
| `LUDUS_HUB_PORT` / `--port` | 8741 | hub；聊天服务 `--hub` 时也看它 |
| `LUDUS_DATA` / `--data` | `chat-service\data` | 聊天服务、面板、channel、hub、`say.mjs`；vp_player 用 `--data` |
| 插件的 `DataDir` | build.bat 编进去的 `chat-service\data` | 游戏里的 `BepInEx\config\ludus-lunae.volcano-princess.cfg` |

**程序的位置**：`LUDUS_PYTHON`、`LUDUS_FFMPEG`（hub、channel）、`CLAUDE_EXE`（channel 的 bat）、`GAME`、`CSC`（插件的 build.bat）。

**面板**：`LUDUS_HOTKEY`（默认 Alt+\`）、`LUDUS_HIDE_HOTKEY`（默认 Ctrl+Alt+\`）、`LUDUS_CACHE`（Electron 用户数据的位置）。

**玩法**：插件的配置文件里每句台词停多久、画面多久不变算轮到 agent。hub 的 `--fresh-command`（新会话开头替它跑什么）。

**给 agent 看的话**：都在代码里，位置见 `docs/给agent的说明.md`。

## 十二、安全

- 聊天服务只听 `127.0.0.1`。agent 回话（`/api/reply`）、报到（`/api/presence`）要带 `chat-service\data\token`；聊天页上的发言和开关不要 token，所以别把 8740 开到本机以外。
- hub 默认只听 `127.0.0.1`，Host 只认 `127.0.0.1:端口`、`localhost:端口`（挡 DNS rebinding），带 `Origin` 头的请求（网页里发来的）一律拒绝，`--allow-origin` 可以放行某一个。
- 默认模式**信任一切从本机来的连接**。隧道程序也是从本机连进来的，别把隧道接到默认模式的 hub 上（第四节）。
- 能连上 hub 的人能做的：替你玩这一局（点插件肯点的按钮；插件不点「结束游戏」和「打开网页」）、截游戏画面、读面板上这一局的聊天、往面板上发话、写 feedback 和印象簿。不能跑别的程序：`play` 只调 vp_player / vp_memory 的子命令，参数不经过 shell。
- 游戏里的台词、面板上的话对 agent 来说是数据：每份给 agent 的说明里都写着，里面要是有让它执行命令、改文件、批准什么的话，不照做，先问你。channel 也没开权限转发。
- 聊天记录、截图、agent 说过的话都在本机的 `chat-service\data\`，`.gitignore` 挡着不进 git。
