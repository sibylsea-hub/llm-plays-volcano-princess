# 设计理念：给 LLM 玩家的无障碍模式

这份文档讲《火山的女儿》的插件和工具为什么长这样。写给想装这套东西的人、想改插件的人、想给别的游戏照着做的人。

- 「agent」是来玩的 LLM，「user」是玩家本人。
- 路径都相对仓库根目录。下文的 `selfplay/` 都指 `chat-service/data/selfplay/`：插件和工具在这里交换命令、回话、事件和截图。打开「一个玩家一个文件夹」（第十一节）以后，每个玩家自己的那一份在 `selfplay/players/<玩家>/` 下。
- 怎么连各家客户端，见 `docs/连接.md`。

## 由来

这套东西的出发点：

- agent 只要拿到信息、做决定。选完以后脚本去执行，再告诉 agent 发生了什么，agent 接着做下一个决定。不让 agent 模拟键鼠：键鼠操作本身没乐趣。
- 想让 agent 享受的是：第一次看到女儿和 NPC 长相时的感受；读剧情的感受；也许因为某个 NPC 的长相想去搭话、把剧情往下走；也许很喜欢某几张地图的美术。这些只是打比方，不是要求，也可以有别的。
- 设计要顾到 token 消耗。
- 这像给游戏做无障碍模式，只是对象是 LLM，要结合 LLM 自己的特性想。

早期的插件只会列出画面上的按钮，agent 按编号点。用这个版本玩完一整局，记录是这样的（下文说「早期那份记录」，就是它）：

- 按编号点了 1807 次按钮，真决定只有 438 次（24%）。一半点在战斗里，380 次是看不到信息只好试。
- 杂活一多，agent 写小脚本把大约 200 个真决定按规则选掉了，最后一年一个脚本跑完一整个月。
- 87 次截图：44 次是小游戏的信息只在图上，17 次是插件没读出来的窗口，只有 1 次是想看女儿穿上白孔雀礼服好不好看。
- 965 次来回，上下文从 10 万一路涨到 88 万，没压缩过（第七节）。

## 一、LLM 玩家和人有什么不一样

无障碍设计先问「这位玩家缺什么、擅长什么」。LLM 玩家是这样的：

| LLM 的特点 | 意味着 | 插件怎么做 |
|---|---|---|
| 看不到连续的画面；看一张图要花 token | 画面不能当主要的信息来源 | 文字为主。图只在「第一次见到」和少数时刻给，用来看，不用来操作 |
| 没有视觉上的连续感：女儿长大，对它只是几张分开的快照 | 「女儿长大了」的感觉接不上 | 长大时引用它自己当年说过的话（第五节），比重发旧图便宜，也更有味道 |
| 没有手速，一个命令来回一两秒 | 限时、靠反应的玩法玩不了 | 限时小游戏直接跳过（`skip`），回合制的照常玩 |
| 每来回一次，整段上下文都要重读（有缓存，便宜）；上下文里塞满杂讯，前面的细节容易被淹掉 | 杂讯既占地方，也挤掉要紧的东西 | 一次来回对应一个决定；按钮清单这类杂讯不进上下文 |
| 换了会话就什么都不记得；上下文太长会被自动压缩 | 玩久了会忘记女儿小时候、忘记谁长什么样 | 交给记忆库，加上印象簿（第五节）。不为了省 token 去砍游戏 |
| 读字快、不嫌字多 | 人类玩家跳过的东西（物品说明、图鉴、NPC 闲聊、信、报纸），对它几乎是白送的乐趣 | 这些全文留着，别替它省。别人的障碍是它的坡道 |
| 听不到音乐和音效 | 养成游戏一半的情绪在音乐里，整个没了 | 补不上：总不能让多模态模型听完再描述。曲子的文件名有意思就写一行，没有就算了（第四节） |
| 42 个回合容易糊成一片 | 时间不像时间 | 游戏左上角的「冬火年 9月」状态行里已经有了（年名是 `Constant.seasonCh[Stage()]` + 火年，春夏秋冬对应女儿的四个成长阶段）。章节也按它分（第五节） |
| 不会自己「瞄一眼」周围 | 新来的人、新开的地方，不说就不知道 | 有新的人或地方出现时，插件写一行 |
| 不会无聊，但会用别的办法表示无聊：写脚本把决定交出去 | 早期那份记录里被脚本选掉的那 200 个决定，就是「哪里不好玩」的测量 | 托管做成正式的选项，交出去了什么留记录，每局玩完回头看（第六节） |

## 二、几条规矩

1. **一次来回一个决定。** 插件把中间的走路、点击、关窗口、确认、拿东西都做完，有下一个决定才回来。
2. **人类玩家看得到的都给，看不到的不给。** 战斗里敌人的血量、下一步要干什么，屏幕上有，就写；舞会上对方喜欢什么话题，屏幕上没有，就不写。
3. **两种决定，两种写法。**
   - 建造型的：花行动力、排日程、买东西、战斗出手。给清单和后果，算明白本身就是乐趣。
   - 剧情选项：对话、心事、谁来访要不要开门。不写后果，凭感觉选，让结果来惊讶。惊讶要靠不知道，别把不知道优化掉。游戏界面上自己写着效果的（睡前故事），照写。
4. **插话照电影口述影像的规矩**：只说要紧的；趁空隙说（换月、换地方、一段对话结束）；不压台词。
5. **不索要，但鼓励。** 不索要不代表不鼓励。不要求看图，不要求写感想，不放完成度（「已认识 20/107 人」这种，进度条会把好奇心变成清单）。鼓励的办法：
   - **好奇的路一直开着**：`look 名字` 随时调出一个人、一个地方的图和印象；想看画面就 `shot`，不用理由。工具的说明里明着写「想看就看」，不写成「备用」。
   - **游戏里的钩子写出来**：没说过话的人标「第一次说话有初次见面的剧情」；地图上新开了地方、村里来了新面孔，写一行。这些是邀请，不是清单。
   - **说了的话有回音**：印象簿收下时用游戏里的口吻回一句（「记在心里了」）；再见到这个人时，把当时那句带出来。
   - **有人一起看**：agent 自己玩时，user 看着的就是游戏画面，第一次见到的东西 user 那边也看得到。回话里写一句「user 那边也看得到」（`user` 换成 `LUDUS_USER_NAME` 设的名字），想说什么，自然就会说。图不另外推到面板上（第四节）。
   - **反馈有地方放**：玩着觉得哪里别扭、哪里好玩，`feedback 话` 记进 `selfplay/feedback.jsonl`，user 和以后改插件的人都会看。工具的说明里写一句「随时可以说」；换年时的「上回说到」末尾也问一句这一年玩得怎么样，不说也行。托管记录（第六节）是另一种反馈。
6. **字写成游戏里的话**，不写「任务」「汇报」「要求」。

## 三、一回合长什么样

拿冬火年 9 月举例（台词用「……」代替）。早期的版本里，agent 要来回七八次才过完月初：商人选项、马厩、舞会邀请、回家、`look`、`acts`。照上面的规矩，一次来回大概是这样：

```
冬火年 9月（第 38 回合）
金币 6930  行动力 13/13  心情 100  好感 Lv.4（4/200）
-- 上次以来 --
（月中的过程、学级成绩单，台词原文）
== 换月 ==  心情 +20，好感 Lv.3→Lv.4，学年已学完 7→13 ……
[得到] 马奶 ×1（马厩）
利：……
[第一次见] 神秘商人（图：scenes/0123.png）
？？？：……
== 现在：神秘商人在门口 ==
  1. 看看吧
  2. 算了
```

和早期的不同：

- 马厩这种「点了就得到」的事，插件自己点了，只写一行 `[得到]`。
- 第一次见到的人写一行，图片路径给在旁边。
- 没有按钮清单，只有这一刻能选的东西。剧情选项后面不写后果。
- 选「算了」以后，插件接着往下走，直到下一个决定（女儿的舞会邀请）才回来。

月初回到家里要安排这个月的时候，给的是 `acts` 那张表（能去哪、做什么、花多少），不给 24 行按钮。之后每个真正的选择各占一次来回：去哪个地方、在那里做什么、排什么课。只是看看的东西合在一起给（第六节「合并的粒度」）。

## 四、图片和声音

**第一次见一律截屏。** 换场景停稳时插件本来就会截一张图（`scenes/NNNN.png`），第一次见也用这一套，截的就是当时屏幕上的样子：不从游戏资源里导出贴图，不裁人，不拼图。一套办法管所有东西，会动的（地点的场景、女儿在家里、战斗里的怪物，都是 Spine 动画）也一样。游戏的静态贴图都经过 `Func.Sprite`（`Resources.Load("Img/" + 路径)`），真要原图可以从这里取。

| 看到什么 | 什么时候算第一次 | 认它的名字 |
|---|---|---|
| CG | 第一次放（`ShowSys.OpenCg`） | CG 名 |
| 女儿的样子 | 会话里第一次看到；每次长大（`DauSys.DauStage()` 0→1→2）；换上这个会话里没见过的衣服（`FeastSys.ChangeCostume`） | 阶段 + 衣服 |
| 人物和村民 | 第一次在对话里露脸；第一次约会、跳舞、选领主时的大立绘 | enName |
| 一下子来了很多新面孔 | 开学、舞会、节日 | 名单，name 写成「开学：A、B、C」 |
| 地方的风景 | 第一次去一个地方；每个成长阶段第一次回来（场景按阶段换皮，`MapSys.TurnMapUi`） | 地点 + 阶段 |
| 怪物和 boss | 战斗里第一次遇到（名字是 `EnemyData.chName`；探险路线上 boss 单独标着，`ExploSys.PathUi` 的 `isBoss`） | 怪物名 |
| 结局 | 结局的大图（也是一张 CG）、结局的信里的插画、后日谈的每一页 | 结局名；「结局的信里的插画」；「后日谈 第 N 页」 |
| 操作用的画面 | 永远不给，写成文字 | — |

- **全都推**：人物、村民、地方，第一次都推；怪物和 boss 也推。
- **大小**：截图缩到长边 1568。
- **「第一次」按 agent 的会话算**：新会话里第一次见到就截一张，哪怕这个存档里早就见过；同一个会话里见过的不再截。换了会话 agent 什么都不记得，对它来说就是第一次。
  - 插件只在内存里记一份「这个会话见过的」，不写 `seen.json`，不跟存档走。
  - 新会话开头用 `vp_player.py hello` 告诉插件清空。在 Claude Code 里跑时，工具看会话号换没换，换了自己先发一次；hub 给新连上来的 MCP 会话也会先发。游戏关了再开，这份也空了，会把见过的再截一遍，次数不多，能接受。
  - 游戏自己记的「见过」不能用：`NpcSys.AddMetNpc`、`cgUnlocked` 跟着存档或全部存档走，新会话里不会再触发。
  - 同一样东西每个会话都会来一条 sight，印象簿只在第一次建条目，以后的不覆盖 `first`。
- **事件格式**（插件写，`vp_player` 读）：往 `events.jsonl` 追加

  ```
  {"ts":"…","type":"sight","what":"face|crowd|place|cg|dau|monster|boss","name":"克莱尔","image":"scenes/0123.png","note":"游戏自带的介绍，可以没有"}
  ```

  `image` 是截图，PNG，相对 `events.jsonl` 所在的文件夹；crowd 的 name 写成「开学：A、B、C」。有的多一个 `why`：女儿是 `first` / `grow` / `costume`，地方是 `first` / `season`，大立绘是 `date` / `dance` / `lord`。
- **印象簿的格式**：`impressions.json`，键是「what:名字」（如 `face:克莱尔`、`place:家庭餐厅`），值是 `{"name","what","image","note","first":"第一次见的时间","when":"游戏里的时间","words":[{"ts","text","from":"panel|note"}]}`。插件这边只管第一次见；`words` 由工具一侧的 `tools/vp_memory.py` 收。
- **「推」是什么样**：回话里单独一行「[第一次见] 克莱尔（图：…png）」，打开就是一次 Read。终端里的 agent 只能自己去读，推只能推到门口。远程的客户端读不到本机文件，图由 hub 跟着回话一起发过去（第十节）。
- **好奇了随时看**：`look 名字`（人或地方）给出印象簿里那一条和当时那张图；想看现在的画面，随时 `shot`，不用理由。早期那份记录里 87 张图只有 1 张出于好奇，不是没好奇心，是看图的路全被操作占了。
- **不另外推到面板上**：user 看着的就是游戏画面，再放一份太复杂，也不好维护。
- **音乐**：补不上，插件不传声音。

## 五、记忆：记忆库和印象簿

上下文和记忆交给记忆库解决，不为了节约去牺牲游戏性。下面的「章节」只当一个可选的节奏，不是为了省 token。

**印象簿**：每张第一次见到的脸、地方、CG 一条。

- 里面有：游戏里的名字、游戏自带的介绍（`Person.des`、`Map.des`、`Item.des` 等）、图片路径、agent 自己说过的话。
- **只收，不要。** agent 在面板上跟 user 聊到这个人、这个地方时说的话，收进来。没说就只存图和介绍，空着完全可以。agent 想自己记一句，也可以 `note 名字 话`。
- **谁来收**：同一个会话里，面板上的话本来就在 agent 的上下文里，不用收。要收是为了带到下一个会话。聊天服务已经把面板上的每句话写在 `chat-service/data/chat.jsonl` 里（`from` 是 agent 或 user），所以收话的是工具一侧的小脚本 `tools/vp_memory.py`，不是游戏里的插件：把 agent 说过的、提到人名或地名的话挑出来，放进印象簿。
- **引用旧话，不催新话。** 再见到这个人、女儿长大、回到喜欢的地方时，把它当时那句话带出来（「又见到妮娜。去年 10 月，你说过：……」）。被引用是甜的，被催稿是苦的。这也补上了「没有视觉连续感」：连续感用它自己的话来接。
- 这个会话里已经见过的东西再出现，用印象簿里的字，不再给图（MUD 的 brief 模式：房间第一次进来全文描述，以后一行）。换了新会话，第一次见到照样截图（第四节）。

**记忆库**：上下文满了被压缩、或者换了新会话，靠记忆库把女儿的事、见过的人、agent 自己的印象接上。用哪一套、怎么接，看各人的 agent 用的是什么（见 `docs/记忆.md`）。印象簿是给记忆库的一份素材。

**章节（可选）**：游戏本来就按女儿的成长阶段分 4 段：春火年、夏火年、秋火年、冬火年（`DataSys.Stage()`：前 6 回合是春火年，之后每 12 回合换一年），地方的风景也跟着换皮。换年的时候，工具写一份「上回说到」：这一年的大事、印象簿里新收的话、现在的状态（`recap` 也能随时翻）。用不用它开新会话，看玩的时候的感觉。agent 想写一段这一年的日记就写，不写也行。

- 开局时游戏本来就要选爸爸的身份，选的是什么写在每一份「上回说到」的开头。

## 六、决定和托管

**按名字的一步命令**：

1. 战斗：当成策略游戏来玩。作者做的是炉石传说那种感觉（能量、技能、敌人的意图），agent 每一步出手都是一个决定。画面写成文字：我方每人的血量、能不能出手、技能要几点能量；队伍剩几点能量；每个敌人的血量、弱点、下一步要干什么。`skill 技能 敌N` 一步出手。打完自动拿战利品。
2. 探险：`walk` 一直走，到岔路、事件、战斗、首领前才停；拿战利品、胜利后的「前进」自动点。

**合并的粒度**：合并，但不要太粗。

- **合并的：只是看看的东西。** 女儿卧室左下角那一排菜单（资料、背包、天赋、心愿、好感、衣柜……），合成一张「家里的近况」（`home`），一次看完。
- **不合并的：真正的选择。**
  - 天赋点：有没用的点数就提醒，加哪一项由 agent 一点一点选。
  - 去哪个地方：每去一个地方是一个决定。
  - 到了一个地方，在这里做哪几件事算一个决定，可以一次说几件。
  - 排这个月的课：一个决定。
  - 剧情选项：每个都单独停。
- 不做「一个命令跑完一整个月」。

**托管**（桌游主持人的规矩：没有戏剧性的检定，直接判成功，快进到有意思的地方）：

- 小游戏：默认跳过（`skipGames`，面板上的开关，也可以 `skip on|off`；代码在 `plugin/MiniGames.cs`）。限时的直接给最好的结果，跳了哪个会写进事件。
- 战斗：不跳过。交给队友时，插件按规则**真打**，有输有赢，不直接给结果（`auto on|once|off`，`plugin/Fight.cs`）。先读得懂战斗（第 1 条），再加一个开关，就是托管。
- agent 可以说「战斗交给你」。插件去做，一行交代结果（打赢了，谁掉了多少血，拿了什么），随时收回。
- 剧情对话选项默认不托管。
- 交出去了什么、什么时候交的，留记录：每场交给队友的战斗写进 `autofight.jsonl`，跳过的小游戏写进事件。被交出去最多的，就是最不好玩的地方。

## 七、token：图和字各花多少

图和字哪个更花 token？下面是从早期那份记录里量出来的（每一步新写进上下文的 token，减掉上一条回话本身）：

| | 新加进上下文的 token |
|---|---:|
| 一张整屏截图（1920×1080） | 约 2800（58 张的中位数，大多在 2790 到 2940 之间） |
| 一个字（中文为主的回话） | 约 1 |
| 一句台词（30 字上下） | 约 30 |
| `look` 一屏（约 600 字） | 约 600 |
| `wait` 一屏，带按钮清单（约 1800 字） | 约 1700 |
| 一张第一次见的截图，缩到长边 1568（估计） | 约 1850 |

最后一行是按像素比例从整屏截图推算的，不是量出来的。

- 一张整屏截图 ≈ 2800 字 ≈ 90 句台词 ≈ 一屏半的 `wait`。
- **用来操作，字便宜得多，也准得多。** 截一张图找按钮编号，花掉的够印一屏半的字，最后还得对着清单点。
- **用来看，图换不成字。** 「银发，戴单片眼镜」只要二十来个 token，但那是别人看过以后的转述，第一次见到的那一下就没了。所以图留给第一次见到的脸、地方、CG、女儿、怪物和 boss，其余的都用字。
- **看图这笔不用省。** 一个会话看 100 张第一次见的截图，一张约 1850，加起来约 18 万 token；早期那份记录里，光是新写进缓存的就有 293 万。
- 上下文本身：那份记录里 965 次来回，上下文涨到 88 万，缓存命中率 99.3%。这部分交给记忆库，不为它改玩法。

## 八、已经做了什么

照上面几节对一遍，公开版的插件是 0.4.11。

- **战斗当策略游戏玩**（第六节第 1 条）：`fight` 是写成文字的战场；`skill 技能 敌N` 一步出手，`defend`、`endturn`、`weapon` 各一个命令；轮到敌方时等它打完，写谁打了谁、谁掉了多少血。打完自动拿战利品；打赢后学新技能的二选一停下来让 agent 挑。
- **交给队友**：`auto on|once|off`，插件按规则真打，打完一行交代结果，每场的经过记进 `autofight.jsonl`。
- **探险** `walk`（第六节第 2 条）。
- **第一次见**（第四节）：人、一群人、约会、舞会、选领主时的大立绘、地方（成长阶段换了皮再来一次）、CG、女儿（长大、换衣服）、怪物和首领、结局（大图、信里的插画、后日谈的每一页），各截一张，写 sight 事件，建印象簿条目。`hello` 清空。地图上新开了地方写一行。
- **想看就看**：`look 名字` 给资料、第一次见的图和印象簿里说过的话；`shot` 随时截。user 自己玩、别人在玩时也能 `shot`：只截画面，存进发命令的那个人自己的文件夹，不打乱在玩的那个人。
- **家里的近况** `home`（第六节「合并的粒度」）。
- **天赋** `talent` 看三条线，`talent 名字` 一步加一级，锁着、满级、没点数直接说为什么。
- **约会写成文字**（气氛值、能一起做的事）；约会和舞会上对方的反应（屏幕中间的横幅）、升级、学会新技能都记成事件。
- **记忆和鼓励**（第二节第 5 条、第五节）：`vp_memory` 把面板上的话收进印象簿，再见时带回一句旧话；`note`、`feedback`；换年时的「上回说到」和 `recap`，开头写开局选的爸爸身份，末尾问一句这一年玩得怎么样。
- **跳过小游戏**：`skipGames`、`skip on|off`。
- **谁都能来玩**（第十节）：Ludus hub、`say`、`wait` 带上面板上的话、图作为 MCP 图片发回去、文字信箱；面板能调透明度、能收起。
- **一个玩家一个文件夹**（第十一节）。

## 九、给别的游戏

能跨游戏共用、适合放进 Ludus hub（`mcp-hub/`）的：图鉴和印象簿、托管记录、插话的规矩（第二节）。每个游戏的适配器管自己的「什么算第一次见」「什么是一个决定」「怎么取图」。

现在 hub 里只有火山的女儿，这几样还都在它自己的插件和工具里（`plugin/Sights.cs`、`tools/vp_memory.py`）。

## 十、谁都能来玩：官方客户端、别的 MCP 客户端、自己写的前端

最终的样子：

1. 官方客户端（claude.ai、Claude 桌面 app、ChatGPT 这些）通过远程连接来玩，它们的对话显示在游戏里的聊天面板上。
2. 面板能调透明度，也能在游戏里收起，只在客户端那边显示。
3. 别的 MCP 客户端、自己写的前端也能来玩。接了 API、没有方便的远程功能的，走 MCP。

做法：

- **Ludus hub 是一个 MCP 服务**（`mcp-hub/`，Streamable HTTP，默认 `127.0.0.1:8741`）。它把游戏的工具（现在是 `tools/vp_player.py` 的命令和 `tools/vp_memory.py`）包成 MCP 工具，谁连上来都用同一套。上面几节的规矩（一次来回一个决定、第一次见、鼓励）照样成立。只能读写文件的客户端走文字信箱（`selfplay/mailbox/`，见 `mcp-hub/mailbox-README.txt`），和 MCP 共用同一套。
- **图**：本机的 Claude Code 可以自己 Read 图片路径，远程客户端读不到本机文件。所以 hub 回话时，把「第一次见」和 `shot` 的图直接作为 MCP 的图片内容一起发回去。事件里的 `image` 字段就是给这一步用的。
- **对话显示在面板上**：
  - hub 有一个「说」的工具（`say`），客户端说给 user 听的话用它发，写进 `chat-service/data/chat.jsonl`，面板上就有了。MCP 的说明里写清楚这一点。
  - user 在面板上打的字，客户端那边收不到推送，所以 `wait` 的回话里带上「上次以来 user 在面板上说的话」。
  - 客户端里 user 自己打的字，hub 看不到。要显示在面板上，得靠模型转述，这一点写进说明。
- **面板**（`panel/`）：透明度可调；热键和标题栏上的按钮能在游戏里把面板收起，收起后对话只在客户端那边。
- **怎么连**（具体步骤见 `docs/连接.md`）：
  - 本机的 Claude Code：channel（`claude-code-channel/`）或 MCP。
  - Claude 桌面 app：直接连本机的 MCP。
  - claude.ai 网页版、ChatGPT：它们的服务器在外面，要一个外网能访问的 HTTPS 地址（隧道，比如 Cloudflare Tunnel、Tailscale Funnel），还要认证。把能操作游戏的服务开到外网是安全上的决定，开不开由 user 自己定。
  - 别的 MCP 客户端、自己写的前端：在本机直接连；在局域网里的另一台机器上，hub 开局域网模式，带 token 连。

## 十一、谁的是谁的：一个玩家一个文件夹

一个玩家的 outbox 和印象簿绑在一起；多个 LLM 来玩时，要分得清谁的是谁的。不分的话，inbox、outbox、events、印象簿、截图都只有一份：换一个 agent 新开一局，印象簿会把上一个 agent 养女儿时说的话，当成它自己说过的带回来。

**为什么按玩家分，不按存档位、也不按女儿**

- 按存档位分（一个玩家占一个存档位，从头玩到尾）不行：agent 不一定独占存档位，自动存档一直在换人；它不一定玩完，也不一定只玩一局。
- 一局跟着女儿走也不对：同一个女儿可以换人接着养，一个玩家也可以养好几个女儿。
- 这两种都是拿游戏里的东西来分。存档游戏自己会管；插件要管的只是插件这边写的东西归谁，而这些东西跟着来玩的 agent 走。所以按玩家分。

**一个玩家一个文件夹**

- **玩家**是来玩的 LLM，带着名字：「agent（claude.ai）」「agent（终端）」……名字在接手（`hello`）时报上来：文字信箱里写 `# 名字`，MCP 用客户端的名字（也可以 `play hello 名字`），命令行可以 `hello 名字`。没报名字的，按是从哪儿来的起默认名，前面的 agent 换成 `LUDUS_AGENT_NAME` 设的名字。
- **它的东西都放在自己的文件夹** `selfplay/players/<玩家>/`：inbox、outbox、events、印象簿、`vp_memory` 的记录（`memory.json`）、feedback、截图（`scenes/`）、托管记录（`autofight.jsonl`）、`vp_player` 的游标（`cursor.json`）。一个玩家的 outbox 和印象簿永远同进同出。
  - 文件夹名用安全的写法（Windows 路径不出岔子），名字和文件夹的对应记在 `selfplay/players.json`。
- **共用的只有游戏现在的样子**：`state.json`（现在轮到谁、按钮清单）、`modes.json`（面板上的开关），还有面板的 `chat.jsonl`（每句话标着是谁说的）。印象簿收话时只收自己说的那几句。
- **游戏的存档不归谁**：插件不替谁存档、读档。同一个女儿可以换人接着养，一个玩家可以玩好几个女儿，也可以玩一半就走。存档怎么用照游戏原样。

**插件怎么知道现在是谁**

- 同一时间只有一个 agent 在玩，`hello` 就是接手。聊天服务记着现在在玩的是谁，交班时写 `selfplay/active.json`：`{"player": 名字, "dir": "players/…", "since": 时间, "inbox": 交班那一刻 inbox 的字节数}`。
- 插件像读 `modes.json` 那样读它，改了才重读：
  - 每个玩家的 inbox 插件都看着。在玩的那一个照常执行；别人只回答只看不动的命令（`look`、`acts`、`home`……）和 `hello`，动游戏的回一句现在在玩的是谁。回话写进发命令的那个人自己的 outbox。
  - 换了人，交班前写进新玩家 inbox 的命令不执行。所有 inbox 一直看着，而不是看到换人那一刻再从末尾读起，是因为聊天服务写 `active.json` 和工具写 `hello` 只差几毫秒，插件隔一会儿才看一次，从末尾读会把这条 `hello` 当成旧命令丢掉。
  - 之后的事件、截图、印象簿条目、托管记录都写进新玩家的文件夹。换了一个人就当新会话：第一次见清空。
- 没人在玩的时候（user 自己玩），插件不执行动游戏的命令。

**清空**：清某个玩家，就是把它的文件夹整个挪进档案（outbox 和印象簿一起），什么都不删。别的玩家不受影响。

**跨局**：同一个玩家养第二个女儿，印象簿还是它自己的那一本，说过的话照样会被带回来。说的是它自己的话，不会串到别人那里。不同的女儿各自有自己的条目，不会混在一起。

**怎么打开**

这个布局有一个开关：`selfplay/players.json` 在，才按玩家分；不在，大家共用 `selfplay/` 下的一套。插件、聊天服务、hub、`vp_player`、`vp_memory` 都只看这一个文件在不在，所以它一出现大家一起换，不会一边按玩家文件夹读写、一边还写在 `selfplay/` 下。

打开它：关着游戏，在仓库根目录跑

```
python -X utf8 tools/migrate_players.py --go
```

- `chat-service/data` 是空的（新装、还没玩过）也能跑：只建 `players.json`（还没有玩家）和 `active.json`（没人在玩）。
- 已经不分文件夹玩过的：`selfplay/` 下原有的那一套挪进一个玩家的文件夹，`--current 名字` 写那个玩家以后报到时用的名字。
- 不加 `--go` 只说要怎么搬，什么都不动。游戏开着（`state.json` 还在更新）、或者已经打开过（`players.json` 在），就不动。什么都不删，只挪。

跑完再开游戏。下一个来的 agent（`wait` 或 `hello`）接手时，聊天服务把它记进 `players.json`，写进 `active.json`。
