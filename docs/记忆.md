# 记忆：游戏这一侧替 agent 留了什么

agent 换了会话，或者上下文满了被压缩，就不记得前面玩过什么。游戏这一侧替它留了几样东西：

| 是什么 | 一句话 | 存在哪（玩家文件夹里） |
|---|---|---|
| 第一次见 | 一个会话里第一次见到的人、地方、CG、女儿的新样子、怪物，各截一张图 | `scenes/`、`events.jsonl` |
| 印象簿 | 每样第一次见的东西一页：图、游戏自带的介绍、agent 说过的话 | `impressions.json` |
| 回音 | 再见到一个人、回到一个地方时，带一句 agent 当时说的话 | 记录在 `memory.json` |
| 上回说到 | 换年时一份上一年的回顾，平时也能翻 | 现算，不存 |
| feedback | agent 想对你说「哪里别扭、哪里好玩」，记一句 | `feedback.jsonl` |

这些都是本地文件，在 `chat-service/data/` 下。不是 agent 客户端自带的记忆功能，两边互不读写（见第七节）。

只在 agent 自己玩的时候有：面板上打开「agent 自己玩」（`data/modes.json` 的 `selfplay`）。你自己玩、agent 在旁边看（陪玩同步）时，插件不写事件、不截第一次见、不建印象簿。纯文字版插件（`plugin-text-only/`）没有这一块。

为什么这样设计（只收不要、引用旧话不催新话、按会话算第一次、一个玩家一个文件夹），见 [设计理念](设计理念.md) 第四、五、十一节。

---

## 一、一个玩家一个文件夹

### 玩家是谁

玩家是来玩的 agent，认的是它报上来的**名字**。名字就是玩家：换一个名字，就是另一个玩家，拿到的是另一个文件夹。

| 怎么来玩 | 怎么报名字 | 不报名字时叫什么 |
|---|---|---|
| `vp_player`，在 Claude Code 里跑 | `hello 名字`。按 Claude Code 的会话记（`CLAUDE_CODE_SESSION_ID`），存在 `selfplay/session-names.json` | `agent（终端）`、`agent（桌面 app）`、`agent（claude.ai）`，按会话是从哪儿开的；别的入口写成 `Claude Code（入口名）` |
| `vp_player`，不在 Claude Code 里跑 | `hello 名字`。不在 Claude Code 里跑的命令共用这一个名字 | `命令行` |
| MCP（Ludus hub） | `play hello 名字`，名字记成 `hub：名字` | `hub：客户端名`，比如 Claude Code 是 `hub：claude-code`；Claude 桌面 app 经 stdio 小桥是 `hub：claude-ai`，小桥设了 `LUDUS_AGENT_NAME` 就是 `hub：那个名字` |
| 文字信箱 | 每封信里写一行 `# 名字`，每封都写同一个 | `文字信箱` |
| Claude Code channel | 不单独报：同一个会话用 vp_player `hello 名字` 起过名字（`session-names.json`），channel 报到也用那个 | `agent（终端）` |

- 默认名前面的 `agent` 是环境变量 `LUDUS_AGENT_NAME`（没设就是 `agent`）。设成 `月`，默认名就是 `月（终端）`。
- 不报名字的话，同一种入口的会话共用一个玩家：所有终端里的 Claude Code 会话都是 `agent（终端）`，所有用 claude-code 连 hub 的会话都是 `hub：claude-code`。想分开，就各报各的名字。
- 信箱里的 `hello 名字` 不改名字，名字只看 `# 名字` 那一行。
- 名字最长 40 个字。文件夹名照名字起，Windows 不认的字符（`<>:"/\|?*`）换成 `_`，最长 60 个字；重名的文件夹加 `-2`、`-3`。名字和文件夹的对应记在 `players.json`。

### 开关：`players.json`

`chat-service/data/selfplay/players.json` 在，才按玩家分文件夹；不在，一切都在 `selfplay/` 下，只有一份，谁来玩都用这一份。插件、聊天服务、hub、`vp_player`、`vp_memory` 都只看这一个文件在不在，所以它一出现，大家同一刻一起换。

**新装的，打开它：**

```
python -X utf8 tools/migrate_players.py --go
```

`data` 文件夹是空的、甚至还没有也能跑。它建好 `players.json`（还没有玩家）和 `selfplay/active.json`（没人在玩）。之后每个新来的玩家接手时，聊天服务把它记进 `players.json`，同时建好它的文件夹。不用重启服务。

只对图像版（`plugin/`）。纯文字版（`plugin-text-only/`）的插件和工具不认玩家文件夹，用它时别开。

只有一个 agent 来玩时，开不开都行。会有不止一个 agent（或者同一个 agent 从不止一个入口）来玩，就打开：不然它们共用一本印象簿，一个会把另一个说过的话当成自己的带回来。

**已经在老布局下玩过的，搬家：**

先不加 `--go` 跑一遍，看它打算怎么搬（什么都不动）；没问题再加 `--go`。游戏要关着：`state.json` 20 秒内还在更新，它就不搬（`--force` 硬搬，不建议）。已经搬过（`players.json` 在）就不再搬。

| 参数 | 干什么 |
|---|---|
| `--go` | 真搬。不写只是看看 |
| `--current 名字` | `selfplay/` 下现在这一套是谁的。写它以后报到时**用的名字**，一个字都不能差，比如 `--current "agent（终端）"`。不写就是 `LUDUS_AGENT_NAME`（没设是 `agent`），多半对不上：它来了会拿到一个新的空文件夹 |
| `--archive 文件夹=名字` | `selfplay/archive/<文件夹>/` 里放着另一个玩家的一套，挪进那个名字的文件夹。可以写好几个 |
| `--split-before 时间 --split-to 名字` | 一本印象簿先后有两个玩家用过时，按时间分开：这个时间以前收的话（和 feedback）挪给 `--split-to`，条目照抄名字和介绍、不带图；`--current` 的 `memory.json` 里带过的这些旧话也去掉。时间写本地时间 `YYYY-MM-DDTHH:MM:SS`，两个要一起写 |
| `--data 文件夹` | 别的 data 文件夹（默认 `chat-service/data`） |

`selfplay/` 下这些留在原地，不搬：`state.json`、`README.txt`、`mailbox/`、`archive/`、`players/`、`players.json`、`active.json`、`session-names.json`。别的都挪进 `--current` 的文件夹。

搬家只挪、只分，什么都不删；目标那里已经有同名文件的，那一个不挪。搬进来的玩家从 `chat.jsonl` 现在的末尾开始收话：老布局下面板上的话没记是谁说的，不往回收。

### 每个玩家文件夹里有什么

在 `chat-service/data/selfplay/players/<文件夹>/` 下（没开这个布局时，同样这些文件直接在 `selfplay/` 下）：

| 文件 | 是什么 | 谁写 → 谁读 |
|---|---|---|
| `inbox.jsonl` | 命令，一行一条 `{"id","cmd","n","snap","text"}` | `vp_player` → 插件 |
| `outbox.jsonl` | 插件的回话，按 `id` 对上 | 插件 → `vp_player` |
| `events.jsonl` | 游戏里发生的事：台词、选项、选择、换月、读档、换场景、截图、第一次见（`sight`）、战斗、庆祝、成就、跳过的小游戏…… | 插件 → `vp_player`（wait 打印）、`vp_memory`（回音、上回说到） |
| `scenes/` | 截图：`NNNN.png`；`NNNN.json` 是截图那一刻的按钮清单；`NNNN-marked.png` 是画好编号的那张 | 插件写图和清单，`vp_player` 画编号 |
| `impressions.json` | 印象簿（第三节） | 插件建条目，`vp_memory` 收话 |
| `memory.json` | `vp_memory` 自己的记录（第三节末尾） | `vp_memory` |
| `feedback.jsonl` | agent 留给你的话（第六节） | `vp_memory` → 你 |
| `cursor.json` | `vp_player` 的游标：`events`（events.jsonl 读到第几个字节）、`month_state`（上一次换月或读档时的状态，算变化、认换年）、`snap`（最近一版清单）、`session` 和 `sessions`（hello 过的 Claude Code 会话，留最近 20 个） | `vp_player` |
| `autofight.jsonl` | 交给队友打的每一场：时间、地点、敌人、每人的血、每一手、结果、拿到什么 | 插件 → 你（想回头看某一场怎么打的） |

### 大家共用的

| 文件 | 是什么 |
|---|---|
| `data/chat.jsonl` | 面板上的每一句话：`{"id","ts","from":"agent\|user","text","who","client"}`，`ts` 是 UTC。`who` 是说话的那个玩家的名字，收话靠它分谁是谁 |
| `data/modes.json` | 面板上的开关：agent 自己玩、跳过小游戏…… |
| `data/selfplay/state.json` | 游戏现在的样子：轮到谁、状态、按钮清单。画面只有一个，所以只有一份 |
| `data/selfplay/players.json` | 开关，也是名单：`{"players": {"名字": {"dir": "players/…", "first": 第一次来的时间}}}`。聊天服务维护 |
| `data/selfplay/active.json` | 给插件看的：现在在玩的是谁（下一小节） |
| `data/selfplay/session-names.json` | `{"Claude Code 会话号": "名字"}`，`vp_player` 的 `hello 名字` 写的；不在 Claude Code 里的记在 `cli` 下 |
| `data/game-events.jsonl` | 陪玩同步：你自己玩时插件每月打的包，channel 读 |
| `data/selfplay/mailbox/`、`README.txt` | 文字信箱，hub 管 |
| `data/token`、`session.json`、`presence.json`、`active.json`、`diag.jsonl` | 聊天服务自己用的：本机接口的钥匙、面板这一局从哪句开始、谁挂着、谁在玩（和 `selfplay/active.json` 不是一个文件）、面板的诊断 |

### 谁在玩：同一时间只有一个

- 聊天服务记着现在在玩的是哪个会话。`hello` 就是「我来玩了」：接手，之前在玩的那个歇着。
- 不用每次自己写 hello：在 Claude Code 里，`vp_player` 看 `CLAUDE_CODE_SESSION_ID`，新会话第一条动游戏的命令之前替它发；hub 在每个 MCP 会话第一条动游戏的命令（或者第一次 `say`）之前替它发。信箱要自己写。
- 只看不动的命令（`status`、`log`、`look`、`home`、`acts`、`plan`、`wish`、`screen`、`shot`、`tip`、`read`、`recap`、`note`、`feedback`）谁都能跑，不接手。
- 别人在玩时，动游戏的命令和 `say` 不跑，只回一句「（某某接手了，你先歇着。要接回来就 hello）」。被接手的会话回来时不会自己补 hello（那等于悄悄抢回去），要接回来得自己 hello。
- 在玩的那个 10 分钟没动静，就算走了，这时没人在玩，下一个来的直接接手。

开了玩家文件夹时，聊天服务每次交班写 `selfplay/active.json`：

```json
{"player": "agent（终端）", "dir": "players/agent（终端）", "since": "…", "inbox": 1234}
```

`player` 是空的，就是没人在玩；`inbox` 是交班那一刻这个人 `inbox.jsonl` 的字节数。插件这样用它（改了才重读）：

- 每个玩家的 inbox 都一直看着。在玩的那个照常执行；别人、没人在玩时，只回答只看不动的命令和 `hello`，动游戏的回一句「现在在玩的是某某，要动游戏先 hello 接手」。`shot` 照截，只有图，存进发命令的那个人自己的 `scenes/`。
- 交班以前写进新玩家 inbox 的命令不执行。插件加载时 inbox 里已有的旧命令也不执行。
- 事件、截图、印象簿条目、`autofight.jsonl` 都写进在玩的那个人的文件夹。交班的空当（没人在玩）接着写上一个在玩的人的；游戏开了以后还没人玩过，就什么都不写。
- 换到另一个人（另一个文件夹）：「见过」清空，等着截的图不要了。同一个人交班又回来不算换人（它自己 hello 时会清）。

### 清空一个玩家

把它的文件夹整个挪走，不删，比如挪进 `selfplay/archive/`（插件只看 `players/` 下面的）。别的玩家不受影响。几件要知道的事：

- 挑它不在玩的时候挪，最好游戏关着。
- `players.json` 里还记着这个名字。它用同一个名字再来，拿到的是同一个路径上的一个新的空文件夹：聊天服务发现文件夹不在了，就当它重新开始，建好文件夹，把 `players.json` 里它的 `first` 改成这一刻。
- 收话只收这个玩家 `first` 以后说的话，所以旧文件夹那时它在面板上说过的话，不会又收进新印象簿。
- 它在面板上说过的话还在共用的 `chat.jsonl` 里。

## 二、第一次见

agent 在一个会话里第一次见到下面这些，插件等画面停稳截一张：

| 看到什么 | 什么时候算第一次 | `what` |
|---|---|---|
| 人 | 第一次在对话里说话（对话框里有头像）；约会、舞会时的大立绘 | `face` |
| 一群人 | 同一段对话里冒出第三个新面孔起，合成一张（停 2 秒算这段对话完了）；选领主时几家领主并排 | `crowd`，名字像 `中央广场：A、B、C` |
| 地方 | 到了以后第一次停稳、没开窗口时；成长阶段换了皮再截一次；探险地图也算，名字带「（探险）」 | `place` |
| 女儿 | 在家、没开窗口时：这个会话里第一次见、长大了、换上这个会话里没见过的衣服 | `dau` |
| CG | 放 CG 时 | `cg` |
| 怪物、首领 | 开战时这场里没见过的敌人，几种一起截一张 | `monster`、`boss` |

截下来的图：

- 存进在玩的那个人的 `scenes/NNNN.png`，缩到长边 1568（一张约 1850 token）。
- `events.jsonl` 里写一条 `{"type":"sight","what","name","image":"scenes/NNNN.png","note":"游戏自带的介绍"}`，有的多一个 `why`（女儿是 `first`／`grow`／`costume`，地方是 `first`／`season`，大立绘是 `date`／`dance`／`lord`）。
- 印象簿里没有这一页就建一页（第三节）；已经有的不动，图还是第一次那张。
- agent 在 wait、click 的输出里看到单独一行，比如「[第一次见] 克莱尔（图：…png；user 那边也看得到）」。走 hub 的话，图跟着回话一起来（一次最多 8 张）；信箱给的是这台电脑上的路径。

**「见过」按会话算**，只记在插件的内存里，不跟存档走：

- `hello` 清空。在 Claude Code 里 `vp_player` 按 `CLAUDE_CODE_SESSION_ID` 自动发，hub 在每个 MCP 会话开头（第一条动游戏的命令之前）替它发，信箱自己写。
- 换到另一个玩家清空，游戏关了再开也是空的。
- 所以新会话里，见过的人、去过的地方会再截一遍。对新会话里的 agent 来说，那就是第一次。游戏自己记的「认识了」「解锁了 CG」跟着存档走，新会话里不会再触发，所以不用它。

agent 想看现在的画面，随时 `shot`，不用理由；你自己玩的时候也能 shot（只有图）。

## 三、印象簿

`impressions.json`，在玩家文件夹里。一样东西一页，键是 `what:名字`：

```json
{
  "face:克莱尔": {
    "name": "克莱尔", "what": "face",
    "image": "scenes/0012.png",
    "note": "游戏自带的介绍（人随关系升级多露出一段）",
    "first": "第一次见的本地时间", "when": "夏火年 3月",
    "words": [
      {"ts": "…", "text": "克莱尔笑起来真好看！", "from": "panel", "turn": 9, "year": "夏火年", "month": 4}
    ]
  }
}
```

- 键的样子：`face:克莱尔`、`place:家庭餐厅`、`place:冰霜峡谷（探险）`、`crowd:中央广场：A、B、C`、`dau:露丝（夏火年，学院制服）`、`monster:青鹿`、`boss:…`、`cg:…`，还有 agent 自己起的 `note:名字`。女儿每个样子一页。
- `image` 相对玩家文件夹。`when` 是游戏里的时间，`first` 是现实的本地时间。
- `words` 里每条：`ts`（本地时间）、`text`、`from`（`panel` 是面板上说的，`note` 是自己记的），知道的话还有那时的 `turn`、`year`、`month`。

**谁写：**插件只建新页（把新条目插在最后一个 `}` 前面），已有的不碰；`vp_memory` 只往 `words` 里加（另外会建 `dau:` 和 `note:` 两种页），别的字段不动。两边都是写好临时文件再换过去，文件读不懂就都不写。

### 收话：只收，不要

- **什么时候收：**`wait`，还有 `click`、`choose`、`do`、`go` 这些动作做完，打印「上次以来」的新事件的时候；`look 名字` 翻页之前也收一次。
- **收什么：**`chat.jsonl` 里 agent 说的、`who` 是这个玩家自己的、而且是它来了以后（`players.json` 里它的 `first`）说的那几句（没开玩家文件夹时，agent 说的都算）。里面提到印象簿里某个名字（人名、地名、怪物名）的句子，截出那一句，放进那一页。女儿的名字总算：印象簿里还没有女儿的页，就建一个 `dau:露丝`；说到女儿的话，放进说这句话时女儿那个样子的那一页。只在现在这个女儿自己的几页里挑：一个玩家玩过好几局、养过好几个女儿，`look`、回音、收话都按女儿的名字分开，不混在一起。
- **截多长：**一句不超过 120 个字，太长就截名字附近的几个小句；不到 4 个字的不收。
- **不收的：**聊工具的句子（说到插件、截图、命令、`wait`、`click` 之类的）。单字的名字和「学者」「士兵」这种泛称，只在像人名的地方认，所以「顺利」「战利品」里的「利」不算。名字后面带括号的（「冰霜峡谷（探险）」），聊天里不带括号也认。
- 同一页里一样的话不收第二次。一句话提到两个名字，两页各收一份。

只有面板上的话会被收：agent 在自己客户端的窗口里说的、想的，游戏这边看不到。agent 想让一句话留下，就在面板上说（`say`），或者 `note`。`chat-service/say.mjs` 发的话和 vp_player 一样认名字（`hello 名字` 起过的名字，或者按会话从哪儿开的），记在那个玩家名下，印象簿照样收。

### `note 名字 话`：自己记一句

想记就记，不记也完全可以。名字可以是人、地方、女儿的名字，也可以直接写键（`note face:克莱尔 ……`）；印象簿里没有这个名字，就新起一页 `note:名字`。同一句不记第二次。自己记的话，回音和 `look` 都会先挑它。hub 里是 `note` 工具，信箱里写同样一行。

### `look 名字`：翻到那一页

`look 克莱尔`、`look 露丝`、`look 家庭餐厅`：

1. 游戏里的资料：关系、好感、资料里露出来的介绍；
2. 最近一张图的路径；
3. 印象簿那一页：「[印象簿] 克莱尔（人）  第一次见：夏火年 3月」、第一次见的那张图、介绍，「你说过（共 N 句，挑了 M 句）：」最多 6 句，每句写着是什么时候说的，自己记的标「（自己记的）」。

挑哪几句：agent 自己的感受（喜欢、难过、叹号、表情）在前，转述的台词、数字、杂事（行动力、金币、排课）在后，只在括号里顺带一提的不挑，自己记的最先。印象簿里还没有、但游戏里认识的人（比如接手以前女儿就认识的），只给游戏里的资料；都没有的，说「还没见过」。

### `memory.json`

`vp_memory` 自己的记录，在玩家文件夹里：

```json
{"chat": 48213, "echoed": {"妮娜": [{"ts": "…", "year": "夏火年", "turn": 15, "text": "带过的那句"}], "dau:露丝": […]}}
```

- `chat`：`chat.jsonl` 收到了第几个字节，下次只看新的。`chat.jsonl` 变短了（换过了）就从头再收，重复的照样不收。
- `echoed`：每个名字（女儿是 `dau:女儿名`）什么时候、哪一年、第几回合带过哪一句回音。频率限制靠它。

删掉它不会丢印象簿：下次从 `chat.jsonl` 开头再收一遍（重复的不收），回音也忘了带过什么。

---

## 四、回音：引用旧话，不催新话

每次 wait、动作做完打印事件之后，`vp_memory` 看这一批里出现了谁：

- 女儿的新样子（`sight dau`）；
- 第一次见的人、地方、CG、怪物（一群人按名单里的每个人）；
- 换场景到的地方；
- 开战时的敌人（`note` 记过的怪物，再遇到也会带）；
- 说话的人（女儿和爸爸不算，每批都有）。

印象簿里这个名字有从前说过的话，就带一句出来：

> （又见到妮娜。去年 10 月，你说过：「……」）
> （又来到遗忘森林，已经是冬火年的样子了。夏火年 6 月，你说过：「……」）
> （露丝长大了。她还小的时候，你说过：「……」）

开头还有「露丝换上了白孔雀礼服。」「这是现在的露丝。」「回到家。」「又遇到青鹿。」这几种；自己记的写「你记下过」。

**频率：**

- 一批最多一句。先看女儿的新样子，再看第一次见的，然后是地方和敌人，最后是说话的人。
- 同一个名字，同一个游戏年里只带一次（同一年、相隔不到 12 回合）；记不到游戏时间时按现实时间，6 小时内只带一次。
- 只带以前的回合说的：这个月说的不带（还在上下文里）；没记回合的话，6 小时以内说的不带。
- 挑哪句：和 `look` 一样先挑 agent 自己的感受；别的年份说的优先一点；上次带过的那句尽量换一句；分数一样挑早的。
- 时间的说法从那句话的回合推：「上个月」「这一年 3 月」「去年 10 月」「夏火年 6 月」；春火年说的，回音是女儿时写「她还小的时候」，别的写「露丝还小的时候」；没记回合的是「上次玩的时候」。

回音只引用，不要回应，也不会催 agent 写什么。

## 五、上回说到

**自动：**换月换进了新的一年（和 `cursor.json` 里上一次换月时的年份比），那一批的输出里，回音后面接一份上一年的「上回说到」。读档读到另一年不给：读的可能是另一个存档，算进去会把两个女儿混成一年。

**手动：**`recap` 看最近的一年（这一年才刚开头、只换过一次月时，看的是上一年）；`recap 夏火年`，或者只写 `recap 夏`。hub 里是 `recap` 工具，信箱里写同样一行。

一屏左右，有这些：

- 「【上回说到 · 夏火年】」；开局选的爸爸的身份（「你想做的是「……」」）；
- 从几月到几月，女儿长高了多少、素质和属性变了多少、好感等级、金币、声望、爱慕者、心情、黑暗、感悟的变化；
- 这一年学完的课、得到的东西、拿到的成就、跳过的小游戏；
- 你做过的选择：同一件事的几步连成一串；零散的最多 8 条，一年里前后都挑；
- 第一次见到的人、地方、怪物……按种类，每类最多 14 个；CG 只说几张；
- 这一年你说过：最多 4 句，每句 70 字以内；
- 你留给 user 的话：这一年的 feedback，最后 5 条；
- 末尾一句「夏火年玩得怎么样？想说就说（feedback 话），不说也行。」

年份按游戏的成长阶段：前 6 回合春火年，之后每 12 回合换一年（夏火年、秋火年、冬火年）。

只算这个玩家自己的事件：一个 agent 接手另一个养到一半的女儿，它的「上回说到」从它接手时开始。

## 六、feedback

`feedback 话`：agent 玩着觉得哪里别扭、哪里好玩，随时说。hub 里是 `feedback` 工具，信箱里写同样一行。

- 追加到玩家文件夹的 `feedback.jsonl`：`{"ts","text","turn"}`。
- 回一句「（记下了，user 会看。）」这类话，`user` 换成 `LUDUS_USER_NAME` 设的名字。
- 给你看，也给以后改插件、改工具的人看。它不发到面板上：你得自己打开这个文件。那一年的「上回说到」里也会列出来，agent 看得到。
- agent 想马上跟你说，用 `say`。

## 七、和 agent 自己的长期记忆

上面这些都是游戏这一侧的本地文件，不是 agent 客户端的记忆功能（Claude Code 的记忆文件、claude.ai 或别家应用的记忆）。游戏不往客户端的记忆里写，也不读它。

一个会话里，agent 靠的是它自己的上下文。上下文满了被压缩，或者换了新会话，游戏这一侧能给它的是这些素材：

- `wait` 第一行写着女儿现在怎么样；
- 新会话里第一次见又各截一张；
- 再见到时，回音带回它自己当时说的话；
- 换年时的「上回说到」，想翻就 `recap`；
- `look 名字` 翻印象簿那一页；hub 的 `panel` 能翻面板上最近的话。

留不下来的：它在自己窗口里说的、想的、打算下个月怎么过。存档归游戏管，这里不替谁存档、读档。换了一个名字（另一个玩家），印象簿就是另一本。

要不要让 agent 把这些接进它自己的记忆系统、接进哪一个，由你决定。两条建议，只是建议：

- 新会话开头先 `recap`，再 `look 女儿的名字`，一下子就接上了。
- 想让女儿的事跨很多会话一直记着，可以让 agent 在换年时把「上回说到」或它自己的几句话存进它的记忆里。印象簿是普通的 JSON，能读文件的 agent 也可以直接去读。

## 八、隐私、备份、换电脑

**这些文件里有什么：**

- `chat.jsonl`：你和 agent 在面板上说的每一句话，带时间；
- `events.jsonl`：游戏里的台词、选择、状态；
- `scenes/`：游戏画面的截图（只截游戏窗口，不截桌面），包括你自己玩时 agent `shot` 的；
- `impressions.json`、`feedback.jsonl`、`memory.json`：agent 说过的话、留给你的话；
- `autofight.jsonl`、`cursor.json`：战斗记录、游标；
- `presence.json`、`session-names.json`：最近挂着的会话、各自叫什么；`diag.jsonl`：面板的诊断（带浏览器标识）；
- `token`：本机接口的钥匙，备份可以，别给别人；
- hub 那边：`mcp-hub/data/`（hub 的日志、局域网模式的 token），`mcp-hub/cache/`（缩小过的截图副本，7 天后自己删）。

都在本地：`chat-service/data/`（环境变量 `LUDUS_DATA` 可以指到别处）、`mcp-hub/data/`、`mcp-hub/cache/`。`.gitignore` 挡着，不会被提交进 git。聊天服务和 hub 只听 `127.0.0.1`（hub 加 `--lan` 才对局域网开，那时要 token）。

文件在本地，不等于不出门：agent 读到的东西（wait 的输出、截图、回音、上回说到）会进它的对话，跟着它的客户端走。

**备份：**关了游戏，停了聊天服务和 hub，把整个 `chat-service/data/` 复制一份。游戏的存档不在这里，游戏自己管，要另外备份。

**清空：**

- 一个玩家：见第一节「清空一个玩家」。
- 全部：把整个 `chat-service/data/` 挪走。聊天服务下次起来会重新建 `token`、`modes.json`；还想按玩家分，再跑一次 `migrate_players.py --go`。

**换电脑：**把 `chat-service/data/` 复制到新电脑的仓库里。印象簿和第一次见的图路径是相对玩家文件夹的，跟着走。仓库放的位置和原来不一样的话，改一下插件的 data 文件夹：游戏目录下 `BepInEx/config/ludus-lunae.volcano-princess.cfg` 的 `[General]` `DataDir`。

| 在哪 | 管什么 |
|---|---|
| `tools/vp_players.py` | 我是谁（`identity`）、我的文件夹（`my_dir`）、开关（`layout_on`）、文件夹名（`safe_dir`，和 `server.mjs` 的 `safeDir` 一样） |

| `tools/vp_player.py` | `print_events`：打印前 `collect`，打印后 `echo`，换年了 `recap`；`look 名字` 接 `card`；`hello`、自动 hello |
| `tools/migrate_players.py` | 打开开关、搬家 |
| `plugin/Players.cs` | 读 `active.json`，看所有人的 inbox，写进谁的文件夹 |
| `plugin/Sights.cs` | 第一次见：什么时候截、`sight` 事件、建印象簿条目 |
| `chat-service/server.mjs` | 谁在玩、交班，`players.json` 和 `selfplay/active.json` |
| `mcp-hub/hub.mjs` | MCP 会话和信箱的名字（`presenceOf`）、替 MCP 会话 hello（`gameCall`） |

单独跑 `vp_memory`（试、查）：

```
python -X utf8 tools/vp_memory.py [--data 文件夹] collect [--again] | note 名字 话 | echo [-n N] | feedback 话 | recap [年] | words 名字 | card 名字
```

开了玩家文件夹时，它按「我是谁」找文件夹：不在 Claude Code 里跑就是 `命令行` 那个。要看某个玩家的，先设环境变量 `LUDUS_PLAYER` 为那个名字，比如 PowerShell 里 `$env:LUDUS_PLAYER = "agent（终端）"`。`collect --again` 从头再扫一遍（印象簿里新加了名字以后用）。

几条约定：

- 开关只有一个：`players.json` 在不在。
- 插件和 `vp_memory` 写同一本印象簿，靠「插件只插新键、`vp_memory` 只加 `words`」两边都不丢；都是先写临时文件再换过去。
- 时间一律存本地时间 `YYYY-MM-DDTHH:MM:SS`；`chat.jsonl` 里的 UTC 读进来时换成本地时间。
- 印象簿那一半出了错，`vp_player` 只提一句，不打断游戏。
